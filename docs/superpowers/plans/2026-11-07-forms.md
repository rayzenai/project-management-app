# Forms (internal round) Implementation Plan

**Goal:** Offices build their own forms in the tracker; signed-in officials fill
them in; the form's side handles responses, exports them and, when a form turns
it on, gets a task from each.

**Spec:** `docs/superpowers/specs/2026-11-07-forms-design.md`

**Architecture:** One access level per person and form,
`WorkspaceAccess::formAccess` (`edit|responses|null`), with
`Form::scopeManagedBy` as its query twin; who may answer is
`WorkspaceAccess::canAnswerForm`, twin `Form::scopeAnswerableBy`. A form's
questions are a JSON schema (`form_versions.schema`, the draft on
`forms.draft`) read only through `App\Support\Forms\FormSchema`; answers are
checked only by `App\Support\Forms\FormAnswers` (visibility, cleaning,
validation), the one truth the browser mirrors. Route → thin controller →
FormRequest `authorize()` → service returning `ServiceResult` →
JsonResource, web and API twins.

## Global constraints

- Every role decision in `WorkspaceAccess` (Forms section), never inline.
- Forms don't depend on `documents.enabled`; only "Open as spreadsheet" does.
- Every JSON column is `jsonb`; tests compare JSON by value.
- No `{@html}`: rich text is TipTap's JSON, checked by `FormRichText` and
  drawn by `components/forms/RichText.svelte`.
- Question and option ids never change or get reused; answers store ids.
- Answers to hidden questions are dropped on every save.
- A task made from a response has `created_by` null.
- Exports of responses are personal documents, never project documents.
- Copy: no em-dashes, sentence case, plain words.
- `composer test` and `npm run lint && npm run format && npm run types:check && npm run build` pass.
- Never write to the local `projects` database; tests use their own.
- Stage only this work's files.

## Schema shape (`FormSchema`)

```json
{
  "languages": ["en", "ne"],
  "steps": [
    { "id": "s_xxxxxx", "title": {"en": "", "ne": ""}, "show_if": null,
      "blocks": [ { "id": "q_xxxxxx", "type": "short_text", "label": {...},
                    "help": {...}, "required": true, "rules": {...},
                    "show_if": {"match": "all", "conditions": [
                        {"question": "q_...", "op": "equals", "value": "o_..."}]} } ] }
  ]
}
```

- Content blocks: `heading` (`text`), `text` (`doc`, TipTap JSON per
  language), `image` (`file`, `alt`), `video` (`url`: YouTube or Vimeo),
  `download` (`file`, `label`), `divider`.
- Questions: `short_text` (`rules.format`: `any|devanagari|latin|digits|pattern`,
  `min_length`, `max_length`, `pattern`), `paragraph` (`min_length`,
  `max_length`), `number` (`min`, `max`, `integer`), `email`, `phone`
  (Nepali mobile), `url`, `date` (`calendar`: `bs|ad`; `earliest`, `latest`,
  or `age_min`/`age_max`/`age_on`), `choice` (`display`: `radio|dropdown`,
  `options`), `choices` (`options`, `min`, `max`), `yes_no`, `scale`
  (`max`: 5|10, `min_label`, `max_label`), `file` (`kinds`, `max_mb`,
  `max_files`), `place` (`depth`: `province|district|local|ward`), `group`
  (`blocks`: questions only, no groups or conditions inside; `min`, `max`,
  `add_label`), `declaration` (`text`; always required).
- Answers: text types a string; `number` a number; `date`
  `{ad, bs}`; `choice` an option id; `choices` a list of option ids;
  `yes_no` a bool; `scale` an int; `file` a list of `form_files` ids;
  `place` `{province, district, local, ward}`; `group` a list of entries
  keyed by question id; `declaration` true.
- Conditions reference earlier top-level questions only. Ops: `equals`,
  `not_equals`, `includes` (choices), `answered`, `not_answered`.

## Tasks

1. **Data and support**: `resources/data/bs-calendar.json` (from
   nepali-date-converter 3.4.0, MIT), `resources/data/nepal-places.json` (from
   @rayzenai/nepali-geo-map, MIT); `BsCalendar`, `NepalPlaces`,
   `FormRichText`, `FormSchema`, `FormAnswers`; unit tests.
2. **Tables and models**: `forms`, `form_versions`, `form_shares`,
   `form_respondent_members`, `form_respondent_organizations`,
   `form_responses`, `form_drafts`, `form_response_events`, `form_files`;
   morph map `form`, `form-response`.
3. **Access**: `WorkspaceAccess` Forms section and scopes; matrix tests.
4. **Builder**: create, update draft, publish, close, reopen, duplicate,
   respondents, shares, stages, task settings; web and API.
5. **Filling**: the form to fill, drafts, uploads, Submit, edit; Forms page
   lists; `FormOpened`, `FormReminder`; My work's forms to fill.
6. **Responses**: table with filters, one response, stages, notes, summary,
   who hasn't answered, Remind, files, ZIP, `.xlsx` download, Open as
   spreadsheet.
7. **Tasks from responses**.
8. **Pages**: Forms page, project Forms tab, builder, fill page, responses.
9. **Docs**: Guide, `CLAUDE.md`, `docs/api.md`.
